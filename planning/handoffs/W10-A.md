# W10-A C7: Lock the AI-spending records

For the owner: The files that record every paid AI call are now locked against the deployed Engineer, and every
Perplexity call of Research and the Leader now carries the same tamper-proof record of who allowed it as Jev's news
checks, so if such a record is missing or altered, the next round is refused with the reason in HQ's activity log and
nothing more is sent. It was tested only with a pretend Perplexity and a made-up key, so no real Perplexity call was
made, and your money rule is unchanged (no limit while testing; your later monthly limit still pauses only the
Perplexity rounds). Nothing needs your decision: the protected package fingerprint changes, which the normal re-pin
at L3 steps 2 and 3 already covers.

## Decisions (reserved block D264–D268)

- **D264 (2026-10-18, implementation default for C7): protected paths for the AI-spending records.**
  `application/budget.py` and `application/gateway.py` (reservations, receipts, allocations, and the gateway that
  reserves before every paid call and settles it after; D261) and the whole `domain/` package are added to
  `PROTECTED_PATH_PREFIXES`. `domain/` is included because the package's acceptance says `kernel/protected_budget.py`
  imports only protected code afterwards, and it imports `domain.clock` and `domain.errors` (the two spending files
  import `domain.money` and `domain.protocols`); the package is five small primitives (the clock behind every
  timestamp, the typed refusals protected code raises and catches, the Decimal helpers, precision, the provider
  protocols; 293 lines) that 20 of the 31 kernel modules already import. The R1 Engineer's write allowlist
  (`artifacts/`, `prompts/`, `strategies/templates/`) never covered `src/`, so no Engineer workflow changes; the
  list is defence in depth and the statement of what broader code authority may never edit. The test checks direct
  imports; package initialisers above them (docstrings, and the paper-mode constants in `trade_graph/__init__.py`)
  are not counted, and the protected package hash pins all source anyway. Not added (not named by D261; listed
  below for a later decision): `contracts/models.py`, `application/model_invocations.py`,
  `application/transport_evidence.py`. Reason: D261, the package bullet, AGENTS.md (accounting and receipt collection
  are not agent-editable).
- **D265 (2026-10-18, implementation default for C7): the Perplexity route bound to protected budget origins.** As
  D258 did for Jev: each reservation of the installed route (`<deployment>:perplexity`) gets an authenticated
  protected budget origin (the protected financial service's MAC, the admitted manifest and controller instance, the
  leased task's paper portfolio and scope, the exact reservation) in the same transaction as the reservation, before
  anything is sent; if the origin cannot be recorded, the reservation is rolled back with it. Dispatch and settlement
  validate it; `commit` validates, writes the receipt, seals the commitment and records its 100% allocation to the
  origin's portfolio in the same transaction (T36's rounds settle searches and agent steps without allocating them);
  `allocate` validates both sides. Before each round, and at start, the route checks fresh cards, a running protected
  controller and a bounded audit (every reservation has its origin and every origin its reservation, the open and
  today's reservations, 500 of this month's in turn). A refusal fails the wake with the reason (D240's visible
  failure, never a silent fallback to the subscription), records a `perplexity_route` activity `refused`, and sends
  nothing; an origin that fails during a round raises `StaleState`, which W6-A's and W6-B's rounds record as a failed
  round with the reason. A hold whose origin fails stays `RESERVED` or `UNCERTAIN` at its maximum (counted by the
  spend guard and HQ), never settled as free. The records stay outside the subscription deployment's financial
  witness (D243, D258), so trading and protection never wait for or fail on them. The route needs the protected
  runtime the service prepares at start (`runtime.protected_deployment.protected`); without it the route is not
  ready and nothing is built. D125, D138 item 4 and D243 are unchanged: the owner's Perplexity spend rule is the money
  rule, the monthly limit pauses only these rounds, the EUR allowance is not consulted, each wake task's allocation
  still bounds a round. Route reservations recorded before this change without an origin are not adopted (none
  exist: the route has never been installed); the audit refuses them and the route stays not ready with the reason
  (fail closed). Reason: the package bullets, W9-A's note, W8-A's finding, AGENTS.md (every paid call reserved and
  receipted; unknown usage unresolved, not free).
- **D266 (2026-10-18, implementation default for C7): one protected route budget in the kernel.**
  `kernel/protected_budget.ProtectedRouteBudget` holds what both reviewed routes share; `NewsRouteBudget` and
  `PerplexityRouteBudget` keep their admission and money rules. W9-A's audit moved without change (its constants are
  now `ROUTE_AUDIT_SECONDS`, `ROUTE_AUDIT_ROWS`, `ROUTE_AUDIT_SWEEP`). The news route behaves as before except that a
  dispatch or settlement without an origin now says so ("a news route dispatch lacks its protected budget origin")
  and a route budget refuses origins bound to another database or clock (the news route reports it as "Jev checks
  are refused (ValueError)"). Reason: no second copy of security code; the news route's tests pass unchanged.
- D267 and D268: not used.
