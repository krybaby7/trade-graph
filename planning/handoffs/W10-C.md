# W10-C C9: HQ asks you when a coin has no safety exit

For the owner: If a coin the Trader bought has had no safety exit for 10 minutes, the HQ tab now shows a "For you to
do" card that says which coin and how much, since when, what the system is doing about it and why its last try
failed, and the card goes away by itself once the exit is in place or the coin is sold. The card only informs you:
it has no button and HQ never trades for you; the account-wide choices stay on Owner controls. Nothing needs a
decision from you, but after the install (step L3) please look at the HQ tab once on your phone and iPad, because it
was checked only in a test browser with made-up numbers; separately, the two news-alarm commands now refuse a mistyped
number in your news alarm settings with a plain sentence instead of a crash.

Branch: `claude/c9-hq-unprotected-card`, head: the commit that adds this handoff's pull request link (code, tests and
docs at `4b8959b`; the handoff first committed in `93c7a72`). Pull request:
https://github.com/krybaby7/trade-graph/pull/24 (not merged).

## Decisions (reserved block D274–D278)

- **D274 (2026-10-18, implementation default for C9): the "no safety exit" card.** A new attention code
  `no_safety_exit` with severity `act` ("For you to do"): a held coin without its safety exit breaks D117's promise
  that every open position carries one, and software has not fixed it within the delay. One card per coin
  (`no_safety_exit:<symbol>`), oldest first, at most three, then one `no_safety_exit:more` card naming the rest (a
  page bound for the 80 KB budget, not a limit on activity, D116). The title says which coin and how much ("SOL/USD:
  5 SOL has no safety exit", the exact quantity, "safety exit" opening the glossary); `since` gives "since 25 min
  ago" and the explanation gives the clock time; the consequence says nothing sells the coins by itself if the price
  falls; "how" says what the system is doing: "Software tries again at every step of the team's service" with the
  last recorded failure in plain words (the raw reason only with "Show technical names"), or that nothing is put on
  while the cancel-all setting is on (until it ends), that the sell-everything setting is selling, that the account is
  stopped, or that nothing happens while the team is off; then "HQ has no button for this; Owner controls has the
  account-wide settings." Link: Trading records. No decision, `can_fix_here` false; it is in the next review prompt
  like every act and watch card. Reason: the C9 package, D115–D117, D188, D246, D251's "marked in the panel only".
- **D275 (2026-10-18, the plan's recommended default): 10 minutes.** A coin's card shows once HQ's clock (the
  dashboard runtime's clock) is at least 10 minutes past the start of its bare stretch; a coin whose start can't be
  read shows at once, because an unknown age is not "fine". Ordinary failures (no quote for a moment, a sweep a few
  seconds later) never reach 10 minutes. Tests drive the delay with the account's frozen clock (9 min 59 s: no
  card; 10 min: card), never with real time.
- **D276 (2026-10-18, implementation default for C9): since when.** The start of the buy's current uncovered stretch,
  from the shared arithmetic on a timeline of saved record times: the fill whose exit was never placed (in a refused
  placement that is the moment of the first `protection_deferred` event), or the moment an exit or close sell that
  covered it ended unsold (its order's last update), for example the owner's cancel-all. Deferral events alone were
  not enough: software records none under a pause that keeps no protection or while the team is off, which would
  hide exactly those gaps. When the times can't be read, the first `protection_deferred` event after the buy's newest
  fill stands in, then the newest fill. A coin's start is its oldest bare buy's.
- **D277 (2026-10-18, implementation default for C9): one arithmetic, read only.** `kernel/day_plan_coverage.py` is
  used by `DayPlanProtection.coverage`, the day plans panel, the card and the Trader's position view, so they never
  disagree. The card caps a coin like the Trader's view (its buys' uncovered parts, never more than is held and not
  already protected), so coins sold another way (the sell-everything setting) get no card while the panel, which
  shows each buy's arithmetic, may still mark that buy; an unreadable ledger never hides a bare coin (no cap then).
  The records are read fresh on every 30-second poll (so the card clears on the next poll), the books only when
  something is bare. Reading starts nothing: tested that the database is unchanged and that placing, sending or
  cancelling would fail the test if called.
- **D278 (2026-10-18, implementation default for C9's small fix): a malformed number in `news-alarm.json`.**
  `news-alarm-poll` and `news-alarm-report` catch `ArithmeticError` (`decimal.InvalidOperation` from a decimal field's
  own check, which Pydantic does not turn into a validation error) like the in-service reader
  (`news_installation._installed_news_poll`) and stop with exit code 2 and "news alarm settings refused (a malformed
  number); nothing was read or sent". The message cannot name the field, because the error does not carry it;
  `contracts/news.py` is unchanged.
