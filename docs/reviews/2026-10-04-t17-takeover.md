# T17 public identity and reproducible operations preflight

T17 remains in progress. This continuation makes the retained local diagnostics
usable from an installed module command and fixes a public instrument identity
gap. It preserves the funded and intended-host acceptance gates. Base checkpoint:
`264e7b0`, isolated branch `codex/t17-takeover-2026-10-04`.

## Implemented slice

Kraken REST tickers previously selected the first returned result and labeled it
with the requested symbol. An ETH/USD response to a BTC/USD request could therefore
become a BTC/USD observation. Tickers now require exactly one book and a native
key matching the requested symbol. BTC/USD and ETH/USD have their known native
aliases; other symbols need matching public metadata first. Metadata acquisition
uses native pair identifiers for normalized symbols, checks complete requested
scope, refuses extra/duplicate/contradictory instruments and retains returned
native aliases only after the complete response validates. Missing/rejected Kraken
error status is refused instead of treating a malformed response as success.
Independent review also found that contradictory native base/quote fields and
pair keys could hide behind a matching `wsname`/`altname`. Native keys and any
supplied native asset fields now independently agree with the normalized pair,
using explicit known aliases; an arbitrary prefix cannot change an asset identity.

The existing host collector now retains stable public failure categories and
attempt/completion times, plus a numeric status for HTTP failures. It retains no
exception text, proxy values or credentials. The new
`trade_graph.application.operations_preflight` installed module exposes capture
and digest-bound verification. The root CLI can reuse its pure
`capture_preflight`/`verify_preflight` APIs. Keys and reports stay private; capture
refuses existing reports and key/source/output collisions. Verification does not
create a missing key or repeat public network requests. Nonzero results distinguish
pending setup from refused/unavailable requested checks; a retained report is not
funded acceptance. See [the runbook](../operations.md).
Follow-up review hardened ancestor traversal and hardlink handling. Directory
components and key/report access use no-follow directory descriptors. Keys require
the current user, private permissions and one file link; preflight also refuses
hardlinked or redirected source files. These checks preserve the original files
and do not silently redirect private evidence through a symlink.
